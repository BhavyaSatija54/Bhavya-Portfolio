EVIDENCE STANDARD

Every strong claim should have somewhere to go.

CLAIM→METHOD→OUTPUT→CHECK→LIMITATION

On the flagship projects, the homepage is only the index. The case study is where the assumptions, calculations, validation and caveats should be inspected.

02 / Research discipline

Build → test → validate → disclose.

I care less about making a model look impressive than knowing where it works, where it breaks and why.

01

Source

Trace material inputs to filings, market data or documented assumptions. No unexplained numbers.

02

Model

Start with the simplest defensible framework, then add complexity only when it changes the decision.

03

Validate

Backtest, reconcile, stress or compare with realised outcomes. Don't confuse a fit with evidence.

04

Disclose

Show limitations, bias and failure cases alongside the headline result. The caveat is part of the result.

03 / Model vs reality

I don't just build models.
I try to break them.

Where a project has a natural external check, I put it next to the headline result. That makes the portfolio less about claims and more about evidence.
