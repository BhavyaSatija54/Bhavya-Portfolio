Market Microstructure & Execution

Closing the Loop

A limit order book simulator that tests its own theory against real order-ID-level outcomes, and reports a mixed result

Most public market-making backtests replay historical order flow and assume a resting quote fills in full the instant price touches it. That is wrong: your own order sits in a real queue, and your own presence changes the book. This project builds the infrastructure to demonstrate and quantify that gap, calibrated on real LOBSTER tick data, ported to C++, and validated against real, order-ID-level reconstructed fills. Every result is reported exactly as computed, including the ones that came back mixed.

02 / The Engineering Problem

Why a price-ladder array, not a tree

Real matching engines avoid tree structures like std::map on the hot path because tree traversal means pointer-chasing with poor cache locality. This engine instead uses a flat array indexed by price ticks from a center point, giving O(1) level access with full cache-line locality for adjacent levels, exactly the access pattern during a book sweep. The order pool uses std::deque rather than std::vector, because a naive vector-based bump allocator would reallocate and move every existing element once capacity is exceeded, silently invalidating every live pointer held by the price-level linked lists and the order-ID hash map, a real and serious bug class in this exact architecture.

The honest partThe standalone engine is roughly 58 times faster than the Python reference, but the integrated end-to-end backtest speedup, actually driving the Python strategy stack through the C++ engine, is only about 1.1 times, 14.3 seconds down to 12.6. Profiling shows Hawkes event generation and pybind11 call-marshalling overhead dominate the integrated runtime. Both numbers are true, they answer different questions, and conflating them would have been the actual dishonesty.
03 / Real-Data Calibration

Root-causing a calibration failure that most projects would hide

Joint alpha and beta maximum-likelihood estimation on the raw LOBSTER data never converged to a finite optimum, the likelihood kept improving toward whatever bound was tested. The cause was diagnosed rather than worked around: 4.2% of consecutive event pairs share an exact timestamp and 58% occur within one millisecond of each other, consistent with a single aggressor order sweeping multiple price levels and generating several messages that are not independent point-process arrivals. The fix, burst deduplication, was then verified to genuinely work, not just run without erroring, by confirming bound-independent convergence across a tenfold range of merge-window choices.

04 / The Central Validation

Does a better-fitting model actually predict better fills

A goodness-of-fit statistic is a statement about the fitted point process. It says nothing by itself about whether the model predicts what a trader actually cares about, whether an order fills and when. This project answers that question directly, reconstructing at the order-ID level exactly which real orders sat ahead of a hypothetical resting order and tracking each one until it filled or the horizon elapsed.

A mixed result, reported as oneAt this sample size, 20 cases with 8 real fills, the recalibrated model does not clearly beat the original on fill-probability accuracy; if anything the point estimate favours the simpler, uncalibrated model on that specific metric. The calibrated model does win on fill-timing accuracy among cases that filled. The honest, actionable takeaway is that the statistical improvement from deduplication is real and verified, but this project has not yet demonstrated it translates into better fill-probability prediction at a sample size this small.
05 / What This Demonstrates

Reporting the result you got, not the one you wanted

It would have been easy to stop at the goodness-of-fit improvement and call the calibration a win. Building the order-ID-level validation harness that could have proven the calibration wrong, and then reporting the mixed result it actually produced, is the difference between a project built to look impressive and one built to be correct. That instinct, that a model earns trust by surviving a test that could have failed it, is the same one behind every project on this site.
