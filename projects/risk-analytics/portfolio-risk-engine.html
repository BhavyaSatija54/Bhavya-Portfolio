Market Risk Analytics

Portfolio Risk Engine

Three VaR methodologies, GARCH volatility, and Basel-style backtesting on one framework

A market risk desk does not trust a single VaR number. It wants the same book measured three different ways, a volatility model that adapts when markets get choppy, and a backtest that tells you honestly when the model has stopped working. This project builds all three as a single, tested Python framework rather than a one-off notebook.

02 / Why Three Methods, Not One

Each VaR method fails differently

Historical VaR needs no distributional assumption and naturally captures fat tails, but it only knows about scenarios that have already happened in the lookback window. Parametric VaR is fast and easy to explain to a committee, but the normal-distribution assumption underestimates tail risk unless it is paired with a volatility model that can react to changing conditions. Monte Carlo VaR, built here with a Cholesky decomposition of the covariance matrix, can simulate scenarios that never occurred historically and preserves the correlation structure across assets, at the cost of being the most computationally expensive and the most sensitive to a badly estimated covariance matrix.

A market risk desk runs all three side by side precisely because they disagree in informative ways. When Historical and Monte Carlo VaR diverge sharply, that is usually a signal that the recent historical window does not represent current market conditions, which is exactly the kind of thing a risk manager needs flagged rather than averaged away.

03 / Methodology

How each VaR method is built

VaR formulas implemented
MethodFormulaKey property
HistoricalVaR = |percentile(returns, α)|No distributional assumption, bootstrap confidence intervals
ParametricVaR = Z_α × σ × √hσ can be standard, EWMA (λ=0.94), or GARCH-forecast
Monte Carlor_sim = μ + L·z, where Σ = L·Lᵀ100,000 simulations, full correlation via Cholesky
GARCH(1,1) specification
Modelσ²_t = ω + α·ε²_{t-1} + β·σ²_{t-1}
Stationarity conditionα + β < 1
Unconditional varianceσ² = ω / (1 − α − β)
Half-lifeτ = −ln(2) / ln(α + β)

Fitting a GARCH model rather than using a flat historical standard deviation is what lets the parametric VaR estimate widen automatically during a volatility cluster and narrow again once markets calm, instead of lagging the true risk by an entire lookback window.

04 / Backtesting Framework

Proving the model works, not just running it

A VaR model that has never been backtested is a guess with decimal places. This engine implements the two tests regulators actually use. The Kupiec Proportion of Failures test checks whether the observed rate of VaR breaches matches the expected rate at the chosen confidence level. The Christoffersen independence test goes further and checks whether breaches cluster together in time, since a model that breaches randomly 5% of the time is well calibrated, but one where all the breaches happen in the same volatile month is not, even if the overall count looks correct.

05 / What This Demonstrates

The skill a market risk desk is actually hiring for

Building a VaR calculator is a tutorial exercise. Building three VaR calculators that disagree in informative ways, wiring in a volatility model that adapts to regime changes, and then subjecting every output to a formal statistical backtest against a regulatory framework is the difference between a risk analyst who reports a number and one who can defend it in a model validation review. That is the standard this engine is built to.
