Shopeasy Consumer Intelligence

Built on 99,441 real orders, not simulated data, with a business story the data actually supports

This is the second version of this project. The first was built on synthetic data around a marketing funnel the dataset could never really support. This version is rebuilt from scratch on the real Olist Brazilian e-commerce dataset, with a warehouse designed before any code was written, and a business story, fulfillment, delivery, retention, and customer value, that the real data actually supports.

02 / A Warehouse Designed Before Any Code Was Written

Getting the grain right, on the right key

Customer analytics here are built on customer_unique_id, the dataset's actual person-level key, not the per-order customer_id that a naive build would silently misuse and that would make every repeat customer look like a first-time buyer. That single modelling decision is what makes the retention and lifetime-value numbers on this dashboard mean what they claim to mean.

Every SQL model and its dbt equivalent were run against a live Postgres instance during development, including a case that caught and fixed a real join fan-out bug in seller performance scoring before it reached the dashboard. That is the difference between a report that was written and one that was tested.

Reported honestly, not rounded upThe 64.5% sentiment-to-star agreement rate is presented as the real result, with the disagreement explained rather than hidden: lexicon-based sentiment methods miss implicit dissatisfaction, like a review saying an item "came incomplete" with no explicit negative sentiment words. A review-cardinality edge case the design anticipated, 547 orders with multiple reviews and 789 duplicate review IDs in the source data, was also confirmed as real rather than assumed away.
04 / Deliberate UX Decisions

Controls that live where they act, not in a global filter bar

A "Monthly versus Cumulative" toggle that only affects one chart has no business living in a filter bar that implies it controls everything on the page. Every control on this dashboard sits directly on the one chart it drives instead, the revenue toggle lives on the revenue trend card, the state filter lives on the revenue-by-state chart, and the count-versus-percent toggle lives on the RFM chart. It is a small decision, but it is the difference between a dashboard that behaves the way it looks like it should and one that quietly confuses whoever is using it.

05 / What This Demonstrates

An analyst who checks the data before trusting the story

The most telling decision in this project is what it does not claim. The original synthetic-data version of this platform was built around a marketing funnel this dataset has no clickstream to support, and rather than keep that story and paper over the gap with invented numbers, this version was rebuilt around the fulfillment, delivery, and retention story the real data actually tells. That willingness to let the data decide the analysis, rather than the other way around, is the core skill a financial or data analyst role is actually testing for.
