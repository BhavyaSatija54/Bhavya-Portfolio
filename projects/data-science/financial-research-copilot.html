Financial Research Copilot

A production-grade retrieval system, not a chatbot demo wrapped around an API call

Most RAG projects are a single embedding model bolted onto a vector store. This one fuses dense and keyword retrieval, reranks with a cross-encoder, auto-ingests SEC filings and Federal Reserve macro data, and ships behind a production FastAPI backend with caching, streaming, and rate limiting, because a research tool an analyst will not actually trust is not much use.

02 / Why Hybrid Retrieval

Dense search alone misses exact terms that matter

A dense embedding model is good at matching meaning, but a financial analyst searching for "Item 1A Risk Factors" or a specific ticker often needs an exact keyword hit that a semantic embedding can blur past. Running FAISS dense retrieval and BM25 keyword search in parallel, then combining their ranked lists with Reciprocal Rank Fusion, captures both signals rather than betting the whole system on one retrieval philosophy. A cross-encoder reranker then re-scores the fused candidate set using the full query-document pair jointly, which is more accurate but far more expensive per document than the initial retrieval, so it only runs on the already-narrowed shortlist rather than the whole index.

Query pipeline
1. Embed querytext-embedding-3-small, 1536-dim vector
2. Dense searchFAISS IndexFlatIP on L2-normalised vectors, top-20
3. Keyword searchBM25Okapi with financial-domain stopword removal, top-20
4. FusionReciprocal Rank Fusion, k=60, unified candidate list
5. RerankingCross-encoder rescoring to a final top-8
6. SynthesisGPT-4o, intent-aware prompt, structured citations
03 / Production Details

Built to be used, not just demoed

The metadata layer runs on SQLite with FTS5 full-text search rather than a flat JSONL file, so filtering by ticker or filing type is an actual indexed query. Query results are cached with a SHA-256 key in Redis, cutting a warm query from roughly 1.2 seconds down to about 80 milliseconds. The API itself supports server-sent-event token streaming, rate limiting, CORS, and gzip compression, the unglamorous infrastructure work that separates a notebook prototype from something a small team could actually deploy.

04 / What This Demonstrates

ML engineering judged on the whole system, not the model choice

Picking GPT-4o and calling an embeddings API is the easy ten percent of a retrieval system. The harder ninety percent, deciding how to fuse two different retrieval signals, when a reranker is worth its added latency, how to structure a metadata store so filtering is actually fast, and how to cache intelligently so a repeated question does not cost a full model call, is what this project is built to demonstrate. That is also the part of the job that decides whether a research tool is fast and trustworthy enough for an analyst to actually keep using.
